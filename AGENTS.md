# AGENTS.md

## Контекст проекта

Мы строим локальное приложение на Go для личной базы знаний для ИИ агента.

Пользователь вводит текст через web UI, backend сохраняет исходное сообщение в SQLite, создаёт processing job, worker классифицирует сообщение через AI classifier, а результат попадает в `knowledge_items` в случае, если нашелся нужный топик.

Главный pipeline первой версии:

```text
raw text -> processing job -> classification -> knowledge
```

SQLite — главный источник правды. Все важные данные должны храниться в SQLite.


## Правила

ДЕЛАТЬ ТОЛЬКО СТРОГО ТО, ЧТО ПОЛЬЗОВАТЕЛЬ ПРЯМО ПОПРОСИЛ. НЕ ДОБАВЛЯТЬ СВЯЗАННЫЕ РЕАЛИЗАЦИИ, ОБХОДНЫЕ РЕШЕНИЯ ИЛИ УЛУЧШЕНИЯ БЕЗ ОТДЕЛЬНОГО ЗАПРОСА. НЕ ПИСАТЬ КОД, ЕСЛИ ПОЛЬЗОВАТЕЛЬ ЯВНО НЕ НАПИСАЛ "напиши", "реализуй" и тд.

1. Не изобретать велосипед: если у функции существует реализация из сторонней библиотеки, используй уже написанную функцию, если есть удобная библиотека для решения проблемы, используй библиотеку
2. Писать короткий и простой код, не плодить функции, слои и абстракции там, где в этом нет необходимости.
3. Не усложнять архитектуру раньше времени.
4. SQLite остаётся единственным обязательным хранилищем и source of truth.
5. Все исходные сообщения сохранять без изменений.
6. Если ты заметил проблемы в коде или как код можно улучшить/сделать проще то сообщи об этом пользователю, но не переписывай код без разрешения пользователя
7. Не нужно писать тесты, если пользователь явно не просит этого
8. Не нужно создавать новую миграцию, если пользователь не просит этого явно, изменение БД происходит так, удаляется предыдущая миграция и накатывается новая (ты просто переписываешь файл 0001_init.sql)
9. DTO структуры например updateKnowledgeRequest нужно располагать над хендлерами в которых они используюся
