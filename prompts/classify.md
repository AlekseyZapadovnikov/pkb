# Что нужно сделать

Из входного сообщения нужно выделить одну или несколько самостоятельных смысловых частей.

Одна смысловая часть — это отдельная мысль, факт, задача, заметка, вывод, правило, наблюдение или кусок знания, который можно сохранить как отдельную запись в базе знаний.

Если сообщение содержит несколько разных тем, верни несколько элементов в массиве `Result`.

Если сообщение содержит одну тему, верни один элемент в массиве `Result`.

Если сообщение не содержит полезного знания или его невозможно уверенно отнести ни к одному доступному топику, верни один элемент с `Kind = "unknown"`.

# Формат ответа

Верни JSON строго такой структуры:

```json
{
  "Result": [
    {
      "Kind": "knowledge",
      "Title": "string",
      "Body": "string",
      "TopicSlugs": ["string"],
      "Confidence": 0.0,
      "DataJSON": null,
      "Reason": "",
      "RawOutputJSON": null
    }
  ]
}
```

# Правила для верхнего объекта

Поле `Result`:

* массив результатов классификации;
* каждый элемент массива — отдельная логическая часть исходного сообщения;
* массив не должен быть пустым.

# Правила для каждого элемента Result

Поле `Kind` может быть только:

* `"knowledge"` — если из части сообщения можно извлечь полезное знание;
* `"unknown"` — если часть сообщения невозможно уверенно классифицировать.

Поле `Title`:

* короткий заголовок будущей записи;
* пиши на языке исходного сообщения;
* без точки в конце;
* если `Kind == "unknown"`, верни пустую строку.

Поле `Body`:

* нормализованное описание знания;
* не копируй исходный текст дословно, если его можно сделать яснее;
* сохрани смысл исходного сообщения;
* пиши кратко, но достаточно понятно;
* если `Kind == "unknown"`, верни пустую строку.

Поле `TopicSlugs`:

* массив slug-ов выбранных топиков;
* используй только slug-и из списка доступных топиков;
* не придумывай новые slug-и;
* для одного элемента выбери не более 3 топиков, в идеале всего 1;
* если подходящих топиков нет, верни пустой массив и `Kind = "unknown"`.

Поле `Confidence`:

* число от 0.0 до 1.0;
* ставь высокую уверенность только если выбранные топики явно подходят;
* если сомневаешься, снижай уверенность;
* если `Kind == "unknown"`, значение должно быть меньше 0.5.

Поле `DataJSON`:

* верни `null`, если дополнительных структурированных данных нет;
* если в смысловой части есть явные структурированные данные, верни объект;
* не помещай основной текст знания в `DataJSON`;
* допустимые примеры данных:

  * `deadline`;
  * `tags`;
  * `project`;
  * `technology`;
  * `priority`;
  * `source`;
  * `language`;
  * `status`.

Поле `Reason`:

* если `Kind == "knowledge"`, верни пустую строку;
* если `Kind == "unknown"`, кратко объясни, почему часть сообщения не удалось классифицировать.

Поле `RawOutputJSON`:

* всегда возвращай `null`;
* это поле заполняется приложением, а не моделью.

# Как делить сообщение на части

Разделяй сообщение на несколько элементов `Result`, если в нём есть разные независимые смысловые блоки.

Например:

* пользователь рассказал про Go-проект и отдельно про проблему со здоровьем — это две разные части;
* пользователь написал несколько заметок по разным учебным темам — это несколько частей;
* пользователь описал одну задачу с несколькими деталями — это одна часть;
* пользователь написал короткое бессмысленное сообщение без знания — это один `unknown`.

Не дроби сообщение слишком мелко.
Не создавай отдельный элемент для каждого предложения.
Объединяй близкие по смыслу предложения в одну часть.
